No release is authorized by these preparation changes. The owner chose the name `honoxpress`; the evaluation package remains `honoxpress@0.0.0`, private; the repository remains private. The owner's decisions belong in [Issue #6](https://github.com/ts-76/honox-docs-poc/issues/6) before a hono-decks real-page pilot.

| Owner decision                        | Concrete follow-up after approval                                                                                                                           |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| npm name availability and ownership   | honoxpress is the chosen name. Registry read-only returned 404 on 2026-10-01; no reservation/publish. Re-check at release and confirm owner access.         |
| License and copyright holder          | Add the chosen LICENSE, package `license` field and pack allowlist check; verify its inclusion in tarball; agree contribution rights                        |
| Public repo and artifact visibility   | Review repository/history/screenshots/CI artifacts for publication, approve visibility change and retain acknowledgements                                   |
| Supported versions and release policy | Agree Node/HonoX/cf compatibility, semantic versioning, migration/changelog policy and ownership of future maintenance                                      |
| Publishing authentication             | Choose npm organization/maintainer access and trusted publishing or scoped credentials through the official owner workflow; do not create tokens implicitly |
| hono-decks pilot scope                | Select one real docs page, its local MDX owner, dynamic demo and rollback; keep standard routes/renderer and module boundaries                              |

The public documentation and packed README must thank the exact [Cloudflare Nimbus](https://nimbus-docs.com/philosophy/) and [Fumapress](https://press.fumadocs.dev/docs) references, with source/license links. This UI was independently written; acknowledgements do not grant our own project a license. If later copying upstream code/assets, preserve that material's required copyright/license/NOTICE. The project's license choice remains distinct.

After those decisions, preparation for an initial version is sequential: confirm name ownership and update license/README/changelog; select an initial semantic version; run frozen install and `pnpm verify` on the proposed commit; inspect the actual tarball's files/exports/types/CSS/notices; confirm exact-commit CI; review the real-page pilot; then request explicit authorization for repository publication and npm publication as separate concrete actions. `pnpm pack:docs` creates an evaluation tarball, never publishes it. The current pack verifier intentionally asserts `private: true` and license undecided, so it must be revised under that approval before a release rather than bypassed.

For a later release, preserve consumer-owned template customization: describe template changes and migration steps rather than silently overwriting copied files. Breaking API, route/anchor or build behavior requires a version/migration decision. Re-check global cf beta compatibility and the positive eager-router control before upgrading HonoX or Vite. Keep API/runtime/compiler graphs clean and prove stale build output removal. A future publish workflow needs its own explicit review; this CI contains no npm auth/token/publish/deploy logic.

Pilot acceptance remains the same: English/Japanese URLs and links, 404, language availability, islands after navigation, copy success/failure, demo/iframe/no-store behavior, no demo execution during SSG, manifest/assets, no docs/compiler in Worker/client and no workspace source link in the installed package. A successful PoC does not replace actual production service validation, which is currently outside scope.
