## Prepare a Hono app

Use npm, pnpm, Yarn, or Bun and an existing Hono app. This guide ends with a two-slide deck. MDX compilation runs locally at build time; the Worker imports generated modules.

## Install the package

`init` creates `hono-decks.config.ts` and an app-owned facade without overwriting existing files. The pilot itself is already configured.

<CopyCode code={"pnpm add hono-decks\npnpm exec hono-decks init"} />

## Create and compile the first deck

Create `decks/welcome/deck.mdx`. Opening frontmatter describes the deck; subsequent separators start slides.

```text
---
title: Welcome
description: My first hono-decks presentation
---

---
layout: cover
---

# Welcome

This deck is served from my Hono app.

---

## Next slide

- Write slides in MDX
- Serve them with Hono
```

Run `pnpm exec hono-decks compile`. Edit source decks and the facade, and leave generated modules to the compiler.

## Mount the generated router

```ts
import { Hono } from "hono";
import { decks } from "./decks";
const app = new Hono();
app.route(decks.mountPath, decks.router());
export default app;
```

Use the configured mount path for both compilation and runtime. In this pilot it is `/demo`.

## Troubleshooting

- Missing generated modules: run the compiler and check `build.root` and `build.outDir`.
- A deck returns 404: mount `decks.router()` at `decks.mountPath`.
- Node modules enter the Worker: use `hono-decks` at runtime and keep `hono-decks/node` in build scripts.
