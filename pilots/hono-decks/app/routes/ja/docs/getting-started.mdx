## Honoアプリを用意する

npm、pnpm、Yarn、Bunのいずれかと、起動できるHonoアプリが必要です。この手順が終わると、2枚のスライドを表示できます。MDXの変換はローカルの開発・ビルド環境で行い、Workerは生成済みモジュールを読み込みます。

## パッケージを追加し設定ファイルを作る

`init`はCLIと実行時の共通設定と、生成コードをアプリにつなぐファサードを作成します。既存ファイルは上書きされません。このpilotは設定済みです。

## 最初のデッキを作ってコンパイルする

`decks/welcome/deck.mdx`を作成します。先頭のフロントマターはデッキ全体の情報、その次の区切りからが1枚目のスライドです。

```text
---
title: Welcome
description: My first hono-decks presentation
---

---
layout: cover
---

# Welcome

This deck is served from my Hono app.

---

## Next slide

- Write slides in MDX
- Serve them with Hono
```

`pnpm exec hono-decks compile`でMDXをHono JSXモジュールへ変換します。ソースとファサードは編集できますが、生成先は直接編集しないでください。

## 生成したルーターをHonoに登録する

```ts
import { Hono } from "hono";
import { decks } from "./decks";
const app = new Hono();
app.route(decks.mountPath, decks.router());
export default app;
```

`decks.mountPath`は共通設定から取得します。このpilotでは`/demo`を使います。

## うまくいかないとき

- 生成したモジュールがない: コンパイラーを再実行し、`build.root`と`build.outDir`を確認します。
- デッキが404になる: `decks.mountPath`で`decks.router()`を登録します。
- WorkerにNodeモジュールが入る: 実行時APIは`hono-decks`から読み込み、`hono-decks/node`はビルド専用にします。
